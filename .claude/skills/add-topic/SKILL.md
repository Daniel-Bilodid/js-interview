# Додавання теми

## Аргументи

`/add-topic [вкладка] <тема>[; <тема>; ...]`

- `вкладка` — необовʼязковий перший токен: `react-native` (або `rn`), `javascript` (`js`), `typescript` (`ts`), `react`, `architecture`. Якщо не вказано — **`react-native`**.
- Кілька тем розділяються `;` — тоді обробляй їх послідовно, повністю завершуючи кожну.

Приклади:
- `/add-topic Як працює React Navigation` → вкладка react-native
- `/add-topic ts Що таке variance у TypeScript`
- `/add-topic rn Deep linking; Push-сповіщення; Робота з клавіатурою`

## Куди що кладеться

| вкладка | файл даних | масив порядку в `src/data/index.ts` |
|---|---|---|
| react-native | `js-interview/src/data/reactnative.ts` | `RN_ORDER` |
| javascript | `js-interview/src/data/javascript.ts` | `JS_ORDER` |
| typescript | `js-interview/src/data/typescript.ts` | `TS_ORDER` |
| react | `js-interview/src/data/react.ts` | `REACT_ORDER` |
| architecture | `js-interview/src/data/architecture.ts` | — (порядок за файлом) |

Усі команди запускай із `js-interview/`.

## Процедура

**Крок 1. Не читай файли даних цілком.** Вони по 1000-1900 рядків і зʼїдають контекст даремно. Потрібні лише id, щоб не зробити дубль:

```bash
cd js-interview && grep -h "    id: '" src/data/*.ts | tr -d " " | sort
```

Придумай `id`: латиниця, нижній регістр, дефіси. Для react-native — з префіксом `rn-`. Id має бути унікальним **серед усіх вкладок**, а не лише у своєму файлі. Id `practice` заборонений.

**Крок 2. Прочитай еталон.** Один раз за сесію прочитай `.claude/skills/add-topic/reference.md` — там повний зразок теми і правила письма. Пиши за ним, не за загальним уявленням.

**Крок 3. Напиши тему.** Обовʼязкові поля і жорсткі межі (їх перевіряє валідатор):

| поле | обсяг | що це |
|---|---|---|
| `title` | 20-150 симв, питання зі знаком `?` | як це питає інтервʼюер |
| `definition` | 2-5 речень, 250-750 симв | ідеальна відповідь senior, готова до озвучення |
| `why` | 1-4 речення, 120-500 симв | яку проблему це вирішує |
| `simple` | 6-14 речень, 600-1600 симв | простими словами, глибоко, без жаргону |
| `related` | 2-4 шт, текст 120-550 симв | супутні теми |
| `codeExamples` | 1-3 шт, код 3-45 рядків | приклади |
| `seniorNotes` | 4-6 шт, по 80-400 симв | нюанси senior-рівня |

**Крок 4. Встав у файл.** Використай Edit із цим `old_string` — він унікальний у кожному файлі даних (це закриття верхнього масиву):

```
  },
]
```

`new_string` — те саме, але з новою темою між `},` і `]`. Формат відступів: 2 пробіли перед `{`, порожній рядок між темами.

**Крок 5. Зареєструй порядок.** Встав `id` у відповідний `*_ORDER` у `src/data/index.ts` — не в кінець, а на місце за складністю, у потрібну секцію коментаря. Для `architecture` крок пропускається.

**Крок 6. Перевір.** Обидві команди мають пройти:

```bash
cd js-interview && npm run check:topics -- <новий-id> && npx tsc -b
```

Валідатор пише конкретні порушення з числами — виправляй, доки не буде `✅`. Не послаблюй правила у `scripts/check-topics.mjs`, щоб пройти перевірку; правило змінюється тільки якщо користувач прямо про це просить.

**Крок 7. Звіт.** Коротко: який id, у яку вкладку, куди в порядку став, що показав валідатор. Не переказуй зміст теми — користувач прочитає її в застосунку.

## Правила письма

Повні правила й еталон — у `reference.md`. Найкоротший виклад:

- **Українською.** Апостроф лише `ʼ` (U+02BC), ніколи `'` чи `’`.
- **Проза — одним рядком**, без `\n`. Абзаци робить `toParagraphs()` сама.
- **Без markdown** у тексті: ні `**`, ні списків, ні backtick-ів. `RichText` підсвічує код автоматично.
- **`definition` — це те, що людина скаже вголос.** Структура: суть → механізм → наслідок. Без «давайте розберемось» і без переліку того, про що буде далі.
- **`simple` пояснює механізм, а не переказує визначення іншими словами.** Аналогія доречна, якщо вона щось прояснює, а не прикрашає.
- **`seniorNotes` — це факти, а не поради.** Кожен пункт має містити конкретику: назву API, число, версію, назву помилки. «Треба стежити за продуктивністю» — сміття. «`getItemLayout` працює тільки при однаковій висоті елементів» — нюанс.
- **Коментарі в коді — українською**, `// ❌` для неправильного і `// ✅` для правильного.
- **Backtick-и в `code`**: рядок обгорнутий у backtick-и, тому всередині екрануй `` \` `` і `\${`.

Заборонені штампи (валідатор їх ловить): «дуже важливо», «варто зазначити», «слід зауважити», «як відомо», «у сучасному світі», «не секрет», «це дуже потужний».

## Якщо тема вже існує

Перевір `grep` із кроку 1. Якщо схожа тема є — не створюй дубль: скажи користувачу, яка саме є, і запитай, доповнити її чи писати окрему під іншим кутом.
